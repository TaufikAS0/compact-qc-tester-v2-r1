# Radio QC workflow1.14.0

One radio panel, two explicit pieces of evidence. Existing stable test IDs/names Radio communication and Radio configuration remain for profile/report compatibility; UI labels them Baca parameter and Tulis + verifikasi. A legacy communication PASS only proved AT entry/channel; its historical checkpoint must not be presented as a new seven-parameter test.

1. Baca parameter radio: temporarily select configuration pin mode, UART1152008N1, wake/AT entry, query seven parameters and version, exit AT and restore only MCP1B4/B5. Ignore draft values. All seven labelled/range-valid replies -> read PASS; a missing/unrecognised field -> UNVERIFIED with bounded per-field TX/RX diagnostics, not an asserted broken module. AT-entry/real transport/control failure can FAIL. A read never proves a write, and a different draft is not a hardware failure.
2. Gunakan nilai terbaca sebagai draft fills only valid current values, explicitly. Polling never overwrites the editable form. Missing fields are visibly unknown and cannot be written blindly.
3. Edit and Tinjau tulis: review exact old/new values and changed keys. No HTTP write request until confirmation. Draft/readId/session/profile/Stop/epoch changes invalidate review. Read older than5min requires reread. Profile-disabled write remains disabled.
4. Confirm: re-enter AT and reread baseline BEFORE any parameter write. Changed/missing baseline -> UNVERIFIED/conflict with zero writes. Write only requested, readable, changed keys; exact labelled +OK acknowledgement per write, then query all again. Changed-key readback mismatch -> FAIL, missing/timeout -> UNVERIFIED, all changed-key ACKs + matching readback -> write PASS for those keys only. No changes is not a write test. Earlier successful writes may remain after a later failure; report partial state and require reread, no automatic rollback/reset/restart.

Read-only AT commands are allowed without target form values. `/api/radio/start` apply=1 additionally requires confirm=1, fields (comma-separated keys), values for selected fields, sessionId, profileRevision and readId from an actual recent successful query. The preflight also compares live selected values with that snapshot. Requests without these are rejected before writes. Existing token/ownership/profile guards remain. No automatic full-parameter write when user changes one value.

QC-RADIO-2 state includes readId/session/profile/age, operation/stage, per-field current/target/diagnostic, writeAttempted/writeVerified/writeMask/ackedMask. Successful completion saves/readbacks the QC checkpoint; failed storage must not be claimed durable. After reboot, historical results/receipt remain in checkpoint evidence; a fresh real read is required before another write. Reset radio invalidates its readId/write proof and leaves other modules unchanged.

Parser only accepts a matching key (Channel alias for CNCFG), optional +, surrounding spaces, ASCII ':'/'=' or UTF8 fullwidth colon, decimal within bounds. Command echo, bare OK, wrong key/out-of-range/trailing junk are rejected. A missing query is retried once, with both replies logged. Raw replies are bounded, JSON-escaped and displayed as text; no uncontrolled command console.

E70-915NW14S is CC1310/15.4 star. Vendor-authored [manual pp17 onward](https://cdn.ozdisan.com/public/product/assets/E70-915NW14S.pdf) documents labelled parameter replies and +OK for writes. This firmware continues the previously supported conservative field ranges; it does not invent LoRa SF/BW/CR. Readback after writing is functional acceptance only: persistence after physical power-cycle, restart activation, RF/range and measured TX power remain separate. No automatic AT+RSTART/factory reset.
